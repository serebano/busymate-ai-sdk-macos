# macOS SDK example app

A real macOS SwiftUI application that consumes the **local BusymateAI Swift package** in the parent directory through `BusymateChatController` and `BusymateChatView`. It uses identity bridge v2 build 2.0.0 and the optional microphone adapter 1.0.0. It contains no copied or mock SDK code.

## Build and open

From the SDK repository root:

```sh
example-app/scripts/build.sh          # Debug, ad-hoc signed, checks entitlements + usage string
example-app/scripts/test-config.sh    # host-side XCTest of the app's configuration logic
open example-app/BusymateSDKExample.xcodeproj
```

The project is generated by XcodeGen in Xcode 15 format (`objectVersion = 60`, `projectFormat: xcode15_0`); regenerate with `xcodegen generate --spec example-app/project.yml --project example-app`. The app targets macOS 12+, is sandboxed with `network.client` and `device.audio-input` ([entitlements](BusymateSDKExample.entitlements)), and declares `NSMicrophoneUsageDescription`. It is ad-hoc signed (`-`), so no team is required; Release builds also enable the hardened runtime. To distribute it, sign with your own Developer ID and notarize.

Select **My Mac** and Run. CI uploads the Release build as `busymate-sdk-example-macos-1.0.0.zip`. That zip is an unsigned (ad-hoc), non-notarized demo: Gatekeeper will block it on another Mac until you right-click › Open or remove the quarantine attribute.

For quick channel or URL experiments: `open BusymateSDKExample.app --args -BusymateDemoChatURL 'https://busymate.ai/support/busyproxy?channel=desktop&locale=ru'`.

## Try the live guest flow

The default URL is the real hosted guest chat `https://busymate.ai/support/busyproxy?channel=desktop&locale=en`, assistant `busyproxy`, with `https://busymate.ai` as the extra exact origin. Open **Chat**, send a message, and tap dictation or voice if the tenant enables it. The SDK adapter asks macOS for microphone permission in response to that tap, never on load.

## Settings pane

The **Settings** tab and the standard macOS Settings window (⌘,) edit the same configuration. **Apply and open chat** disposes of the previous chat and installs a new `BusymateChatController` before its first load.

| Control | What it configures |
|---|---|
| Assistant slug | `Config.assistant` (validated slug). |
| Chat HTTPS URL | The URL loaded in the WKWebView, including tenant query parameters. |
| Locale | Replaces the URL's `locale` parameter (BCP-47 shape such as `en`, `pt-BR`); empty keeps the URL's own. |
| Exact HTTPS origins | `Config.origins`, which are also the adapter's and the navigation allow-list. The chat URL's origin must be allowed. |
| Enable tap-triggered OS permission | `microphone:` true/false. When off, WebKit media requests are denied. The current macOS microphone state is shown read-only and never prompts. |
| Mode: Guest / Identified (mint callback) | Guest: `account` returns nil and no mint request is made. Identified: `account` returns the entered ID and `mint` POSTs to your endpoint. |
| Account ID, mint endpoint, session token | Identified-mode inputs. The token is optional, held in memory and sent only as a Bearer header to your endpoint. |
| Handle close through onAction / onClose fallback | Supplies `Config.onAction` / `Config.onClose`, or nil when off. |
| ASWebAuthenticationSession for auth opens | Sets `authCallbackScheme` to `bmaisdkdemo` (registered in Info.plist) or nil. |
| Forward accountChanged() | Applies the identity fields and calls `BusymateBridge.accountChanged()`. |
| Renderer recovery forwarding | Calls the real `contentProcessDidTerminate`; it does not simulate a crash. |
| Reset | Restores guest defaults. It does not reset the OS microphone permission. |

## Your authenticated backend

Guest mode makes no mint request. Identified mode needs your real tenant backend: it must authenticate the app session and sign fresh single-use assertions. Each callback POSTs `nonce`, optional `aud` and `reason`, plus the bridge-supplied `assistant` and `origin`, bypasses caches and **refuses all HTTP redirects**. The response must be `{"token":"…","nonce":"<same nonce>"}`; 401/403 means signed out, and anything else fails closed. Entering an account ID is not a login.

## Events

The **Events** tab logs SDK callbacks (`loaded`, refused navigations by host, external opens by host, WebKit media decisions, process termination), mint outcomes, and the public `busymate-bridge` event names `resume`, `state`, `restored` and `auth`. It never logs payloads, account IDs, tokens, nonces, full URLs or audio. The list is capped at 100 entries and is not persisted.

## What is and is not verified

CI builds the app (Debug and Release), checks its entitlements and usage string, and runs the configuration tests (default guest URL, origin and locale validation, identified mode without a backend, callback on/off, nonce-correlated mint mapping, header-injection refusal, and redirect refusal against two loopback servers). The real macOS microphone dialog, your backend's identified flow and notarized distribution must be verified by you on a real Mac.
